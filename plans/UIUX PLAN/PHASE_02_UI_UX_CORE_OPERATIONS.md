# Phase 2 — Core Operations UX

## Objective
Replace the current dense all-in-one registrant dashboard with separate operational workspaces.

## Implement
- Dashboard.
- Registrants.
- Payments entry point.
- Tickets.
- Attendance.
- Certificates.
- Event switcher.

## Key Change
Do not put payment, ticket, email, Drive, edit, delete, and messaging actions into one dense table.

## Participant Interaction
- Row click opens right-side detail drawer.
- Drawer has identity summary, status timeline, key actions, and related records.
- “Open full detail” is available for deep work.

## Acceptance Criteria
- Current event is always scoped.
- Registrant list is focused on identification and next action.
- Drawer preserves list context.
- Main page contains no redundant action clusters.
